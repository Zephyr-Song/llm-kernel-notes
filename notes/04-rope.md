# 04 · RoPE：相对位置编码、外推与长上下文

> 对应代码：`code/03_rope.py`（**重点看 `prove_relative_property()`**）

## RoPE 做了什么

对 Q 和 K 的每一对相邻维度 `(x_i, x_{i+d/2})` 施加一个二维旋转，旋转角度 `m · θ_i`：

```
θ_i = base^(-2i/d)                    # 频率随维度递减
f(x_1, x_2, m) = (x_1 cos(mθ) - x_2 sin(mθ),
                  x_1 sin(mθ) + x_2 cos(mθ))
```

关键：**只对 Q、K 旋转，不对 V 旋转**（因为 attention score = q·k）。

---

## 核心性质证明（手推一遍就 forever 记住）

**命题**：`<R_m q, R_n k>` 只依赖相对位置差。

```
<R_m q, R_n k>
  = q^T R_m^T R_n k
  = q^T R_{n-m} k            ← 只剩相对位置！
```

用到的两个事实：
1. 旋转矩阵 `R(θ) = [[cosθ, -sinθ], [sinθ, cosθ]]` 是正交的，`R(θ)^T = R(-θ)`
2. 旋转的复合：`R(α)R(β) = R(α+β)`

`code/03_rope.py` 里`prove_relative_property()` 用 float64 实测验证了这点——相同的 `m-n` 得到**完全相同**的分数（极差 < 1e-9）。

**其他必须知道的性质**：

| 性质 | 说明 |
|---|---|
| **保距** | `‖R_m x‖ = ‖x‖`（正交变换）。所以旋转不会改变向量的模长，缩放行为和其他 attention 变体一致 |
| **位置 0 是恒等** | `θ=0 → cos=1, sin=0` → 位置 0 完全不旋转 |
| **形状不变** | 旋转不改变 tensor shape，所以可以融合进 Q/K 投影的输出 |

**为什么 RoPE 优于绝对位置编码**：绝对位置编码（sinusoidal/learned）在训练长度外没有定义，而 RoPE 的表达式对任意位置都有定义——这是它"看起来能外推"的数学基础。

---

## base = 10000 的设计意图

`θ_i = 10000^(-2i/d)`，指数位递减 → 低维频率高（快），高维频率低（慢）。

**类比时钟**：秒针走得最快（提供高精度）、分针/hour 走得慢（提供大范围）。多组不同周期的"指针"组合唯一确定任意位置。

```
head_dim=128 时的频率分布（跑代码看实际数字）：
  i=0:   θ=1.000,周期 6.3 token    ← 只能分辨相邻几个 token
  i=32:  θ=0.0625, 周期 100 token
  i=63:  θ=0.0078, 周期 805 token  ← 一个完整周期覆盖约 12.6K token
```

**base 越大** → 频率整体越低 → 长距离分辨能力越强，但相邻 token 区分越粗。

现代模型的选择：
```
LLaMA-1: base=10000
LLaMA-3: base=500000    (支持 8K→128K)
Qwen2:   base=1000000
Yi/DeepSeek: 为长上下文专门设定
```

## 外推为什么会崩

### 原因 1：低频维度从未见过一个完整周期

训练长度 64 时，很多维度的 `m·θ < 2π`，模型只见过编码空间的一小部分。外推到 512 时进入完全未训练的区域。

代码里会打印：`训练时未完成一个完整周期的维度数 / 总维度数`——通常是一大半。

### 原因 2：PIT（Position Interpolation Theory）—— 注意力分布偏移

这个更隐蔽：

**注意力分数 `q·k` 的方差随位置增大而上升 → softmax 越来越尖锐 → 注意力过度集中。**

模型训练时看到的是平缓的注意力分布，推理时突然变得极端，输出退化。代码里通过测量不同位置的 `scores.std()` 和 `softmax.max()` 展示了这一点。

**这是外推失败的真正机制**，不是"位置编码没定义"那么简单。

---

## 修复方案

### 线性插值（PI）—— 最差

把所有位置除以缩放因子 `s`。高频和低频一起被压缩，高频精度全部丢失。

### NTK-aware 插值（bloc47 提出）

**思路**：只改 `base`，让低频维度几乎不变、只有高频被压缩。

```
base' = base * s^(d/(d-2))
```

代码里 `ntk_interpolation()` 会对比两种方案在各维度上的频率变化：

| 维度 | 朴素 s=8 | NTK-aware |
|---|---|---|
| i=0（高频） | 变化大，细节丢失 | 变化极小，**保留精度** |
| i=63（低频） | 变化大 | 被压缩，**承担外推** |

这正是我们想要的分工：**高频保精度，低频扛长程。**

> LLaMA-3 用 base=500000 支持 128K 上下文，本质就是这个思路。

### YaRN（当前主流）

进一步改进：**按维度分段处理**

```
高频维度（波长短） → 不插值，保持原样   ← 保局部精度
低频维度（波长长） → 完全插值           ← 承担长程
中间维度          →平滑过渡
```

**额外引入注意力温度修正**：
```
m_scale = 0.1 · ln(s) + 1
```

计算 attention 时额外乘上这个系数，补偿 PIT 导致的分布尖锐化。

### 方案对比

| 方法 | 做法 | 缺点 |
|---|---|---|
| 线性插值 (PI) | 位置全除 s | 高频信息也损失，效果最差 |
| NTK-aware | 只改 base | 所有维度都被压缩 |
| **YaRN** | 分段 + 温度修正 | 实现复杂，但效果最好 |
| LongRoPE | 渐进式扩展 + 非均匀频率 | 需要分阶段训练 |

---

## 重要现实：没有免费的长上下文

现代模型（Llama 3.1+、Qwen2.5、Yi）的做法是：

```
1. 训练时做 8K → 128K 的渐进式扩展（LongRoPE 风格，多阶段继续训练）
2. 训练后调整 base 到 500k
3. 推理时不再做任何动态插值
```

**关键结论：所有能上生产的 128K/1M 上下文模型都做了针对性的继续训练。** 别指望换个 base 就白嫖长上下文。

这和你的 SafeBARS 也有关系——如果你评测里涉及长上下文场景，「模型宣称的上下文长度」和「实际可用长度」是两回事，评测设计要注意区分。

## 实战要点

### 实现顺序（容易搞错）
```
Q,K 投影 → 施加 RoPE → attention → @V
         ↑
    只对 Q,K，不对 V
```

### KV cache 场景的优化
**不要全量计算 cos/sin 表**，只算新 token 位置的：
```python
# 错误：每次都算全表
cos, sin = build_rope_cache(seq_len, dim)

# 正确：只算当前位置
cos_pos, sin_pos = build_rope_cache(1, dim)[0][cache_len]
```
现代实现还会在 GPU 上预缓存整张表并用 GPU 计算（避免 CPU-GPU 同步），见 llama.cpp 的 `rope_cache`。

### 常见坑
| 坑 | 症状 |
|---|---|
| 忘了 clamp `-inf` | 输出 NaN |
| rotate_half 的实现顺序写反 | 位置 0 之后所有位置错乱 |
| 用 `head_dim/2` 作为 sin/cos 维度但没 cat | shape 不匹配 |
| KV cache 里位置索引错了 | 重复生成或跳字 |
